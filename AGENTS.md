# AGENTS.md — Правила для AI-агентов CRYPTORA

> **Проект:** CRYPTORA — Crypto Market Intelligence Terminal  
> **Слоган:** «Рынок. Данные. Решения.»  
> **Статус названия:** Рабочее название проекта (юридическая и товарная доступность подлежит отдельной проверке).  
> **Главный принцип:** Это долгосрочный инженерный продукт, а не одноразовая генерация сайта. Не пытаться реализовать весь продукт одним проходом.

---

## 1. Обязательный протокол входа агента (BEFORE CODING)

Каждый агент, начинающий сессию или новый подэтап в репозитории CRYPTORA, **ОБЯЗАН** прочитать документы строго в следующем порядке:

1. **`AGENTS.md`** (этот файл — базовый кодекс и правила работы)
2. **`docs/agent-plan/00-README.md`** (общая дорожная карта и структура этапов)
3. **`docs/agent-plan/STATUS.md`** (текущий статус проекта — **единственная точка остановки и передачи эстафеты**)
4. **`docs/agent-plan/RULES.md`** (жесткие технические и архитектурные инварианты)
5. **Документ текущего этапа** (например, `docs/agent-plan/01-VISUAL-FOUNDATION.md`)
6. **Документацию затрагиваемой подсистемы** в папке `docs/` (например, `docs/MARKET_DATA.md`, `docs/DERIVATIVES.md`, `docs/DESIGN_SYSTEM.md`)
7. **Существующий код и тесты** затрагиваемой области перед внесением любых правок.

---

## 2. Обязательный протокол выхода агента (AFTER CODING)

Перед завершением сессии агент обязан выполнить следующие шаги:

1. **Typecheck:** `npm run typecheck` — 0 ошибок TypeScript.
2. **Unit Tests:** `npm test` — все юнит-тесты и тесты контрактов проходят.
3. **Build:** `npm run build` — чистая production-сборка без предупреждений об отсутствующих модулях или сломанных типах.
4. **E2E Tests:** `npm run test:e2e` — браузерные сквозные тесты успешно завершены.
5. **Актуализация документации:** обновить `docs/` и соответствующие файлы этапов, если были приняты архитектурные решения.
6. **CHANGELOG.md:** добавить запись о выполненных изменениях с датой и версией.
7. **STATUS.md:** обновить файл `docs/agent-plan/STATUS.md` со всеми обязательными полями:
   - Что сделано
   - Что не сделано
   - Результаты тестов (typecheck, unit, build, e2e)
   - Известные ограничения
   - Следующий конкретный подэтап
   - Версия
   - Commit hash
   - Статус Git remote / push
8. **Осмысленный Git commit:** зафиксировать изменения на текущей рабочей ветке с информативным сообщением.

> **Правило Git Remote:**  
> Если удаленный репозиторий недоступен для прямой отправки или не настроен для push без аутентификации, **НЕ ПРИДУМЫВАТЬ** фиктивные URL и **НЕ ДЕЛАТЬ** ложный `git push`. Зафиксировать локальный коммит и отразить текущий статус push в `STATUS.md`.

## 3. Критические архитектурные правила

1. **Никакого обмана с данными:**  
   На этапе 1 все данные являются демонстрационными. Везде, где пользователь может принять цифры за живой рынок, обязательна плашка или бейдж: **«Демонстрационные данные»** / **«Demo Data»**.
2. **Детерминированный Demo-слой:**  
   Запрещено использовать `Math.random()` для генерации дергающихся «живых» котировок. Данные должны быть фиксированными, типизированными через Zod/TypeScript и поступать через абстракцию `MarketDataProvider`.
3. **Изоляция контрактов:**  
   UI-компоненты не зависят напрямую от реализации моков. Переключение с `DemoMarketDataProvider` на `LiveMarketDataProvider` на будущих этапах должно производиться через подмену провайдера без переписывания страниц.
4. **Сайт НЕ является биржей:**  
   - Не принимать средства пользователей.
   - Не хранить seed-фразы и приватные ключи.
   - Не запрашивать торговые API-ключи бирж.
   - Не исполнять реальные сделки.
   - Никаких автоматических торговых ботов с исполнением.
   - Не обещать гарантированную прибыль.
5. **AI — только финальный объясняющий слой:**  
   AI никогда не генерирует цены, funding, open interest или ликвидации. AI работает строго поверх структурированных фактов детерминированного аналитического движка.
6. **Оценка ликвидаций:**  
   Фактическое событие ликвидации (`Actual liquidation event`) строго отличается от расчетного уровня (`Estimated liquidation level`). Любые тепловые карты уровней обязаны маркироваться как `MODEL / ESTIMATED`.
7. **Backtesting без подглядывания (No Look-Ahead Bias):**  
   Будущий движок бэктестинга обязан использовать неизменяемые исторические срезы, учитывать комиссии, funding, проскальзывание и разделение выборки на train/test.

После выполнения этапа агент **ОСТАНАВЛИВАЕТСЯ**. Не продолжать следующий этап самовольно. Дождаться проверки владельца проекта и постановки следующей задачи. Единственный источник актуального состояния — `docs/agent-plan/STATUS.md`.
