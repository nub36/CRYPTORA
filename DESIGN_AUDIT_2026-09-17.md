## 1. Резюме

Дизайн-система CRYPTORA — **зрелая и дисциплинированная**: токены через CSS-переменные, темы DARK/LIGHT переключаются без «мёртвых зон» (98,9–99,6% пикселей меняются, включая графики), ни одного горизонтального переполнения на всех разрешениях, ноль захардкоженных hex-цветов, все контролы имеют доступные имена, есть `prefers-reduced-motion` и глобальный focus-ring.

Но аудит нашёл **один критичный для визуальной идентичности дефект** (продакшен никогда не рендерит фирменные шрифты из-за CSP), **системное нарушение собственного стандарта тач-таргетов на мобильных** (до 51 мелкого элемента на страницу) и **4 типа контрастных нарушений** (109 измеренных случаев), из которых два обходят собственные тесты-охраны проекта.

## 3. Критичные находки

### Д1 🔴 Фирменные шрифты НЕ ЗАГРУЖАЮТСЯ в продакшене (CSP блокирует Google Fonts)

`index.html:24-26` подключает Inter и JetBrains Mono с `fonts.googleapis.com` / `fonts.gstatic.com`. Но CSP в **обоих** прод-конфигах:

- `server/productionServer.js:75-76` → `style-src 'self' 'unsafe-inline'; font-src 'self' data:`
- `nginx/cryptora.conf:67` → то же самое

внешние стили и файлы шрифтов **не входят в whitelist** → браузер молча блокирует оба запроса → терминал рендерится системным шрифтом (`system-ui` / `monospace`).

**Последствия:** вся типографическая идентичность дизайн-системы («sans Inter для UI, mono JetBrains Mono для чисел», §4 DESIGN_SYSTEM) в проде не существует. Метрики `tabular-nums`/выравнивание чисел работают на фолбэке. Все скриншот-QA прогоны (в песочницах без сети) фактически тестировали фолбэк-шрифт, т.е. совпадали с продом случайно.

**Решение (правильное — self-hosting, заодно GDPR-безопасно для EU-трафика):**
```bash
npm i @fontsource/inter @fontsource-variable/jetbrains-mono
```
```ts
// src/main.tsx (или index.css @import)
import '@fontsource/inter/400.css'; import '@fontsource/inter/500.css';
import '@fontsource/inter/600.css'; import '@fontsource/inter/700.css';
import '@fontsource/jetbrains-mono/400.css'; import '@fontsource/jetbrains-mono/500.css';
```
Удалить `<link>` из `index.html`. Шрифты попадут в бандл с `font-src 'self'` — CSP менять не нужно. Затем прогнать скриншот-QA заново — метрики строк/таблиц изменятся.

### Д2 🟠 CoinIcon: буква 10px с контрастом до 1.8:1 — обходит собственную охрану

`src/components/common/CoinIcon.tsx:36-37`: `fontSize = Math.max(10, size * 0.45)` — **inline-стилем**, поэтому тест `typography.test.ts` (сканирует классы `text-[9px]/[10px]`) его не видит. Замер по таблицам `/market` и `/futures` (иконки 20–22px): кегль буквы **10–10.8px** (ниже собственного минимума 11px), контраст белой буквы на фирменном цвете круга — **1.8–3.25:1** (нужно 4.5:1, для UI-графики минимум 3:1).

**Решение:** `fontSize = Math.max(11, Math.round(size * 0.5))`; для светлых цветов фона (#F7931A, #F0B90B, #00D4AA) — тёмный текст `#0f172a` вместо белого (или полупрозрачная тёмная подложка под буквой). Букву пометить `aria-hidden` (тикер рядом и так называет актив; `aria-label` на `div` без `role` скринридеры игнорируют — сейчас это мёртвый атрибут). Добавить в `typography.test.ts` проверку inline `fontSize` в `CoinIcon`.

### Д3 🟠 Мобильные тач-таргеты: 21–51 элемента ниже 28px на страницу

Замер на 390px (свой стандарт DESIGN_SYSTEM §5 — `min-h-[32px]`; WCAG 2.2 AA — 24px):

| Страница | Элементов < 28px | Типичные случаи |
|---|---|---|
| `/market` | **51** | ссылки тикера в шапке **22px** высотой; кнопки «Избранное» ★ **22×22px** (`MarketPage.tsx:256`, `p-1` без минимальной зоны) |
| `/screener` | 51 | те же строки таблицы |
| `/coin/BTC` | 45 | переключатели таймфреймов, элементы пульса |
| `/strategies` | 40 | ссылки-версии архива |
| `/overview` | 25 | ссылки «Все деривативы» **16px**, безымянная ссылка-спарклайн **35×19px** |
| прочие | 21–29 | чипы фильтров, пагинация |

Документация заявляет «Сенсорные зоны на мобильных экранах увеличены» — **измерение это опровергает**.

**Решение:** паттерн «растянутая зона»: визуальный элемент 22px, но hit-area ≥ 32px — `relative` + `::before { position:absolute; inset:-5px }` или `py-1.5` на обёртке ссылки; для ★ — `min-w-[32px] min-h-[32px] flex items-center justify-center`. Тикер в шапке на мобильных: `min-h-[36px]` на ссылке. Добавить e2e-инвариант «на 390px все interactive ≥ 28px» (у проекта уже есть каркас таких проверок в `uiRegression.spec.tsx`).

### Д4 🟠 `text-slate-600` для реальных данных — 2.52:1 (15 вхождений)

Собственное правило проекта: минимальный серый — `slate-500` (≥4.5:1). Но `slate-600` используется для **читаемого контента**:

- `CoinDetailPage.tsx:839` — «(3.2bps)» в таблице пар — реальные данные;
- `DataSourcesBadge.tsx:143`, `AiExplanationPanel.tsx:231` — сноски бейджа источников;
- `CoinDetailPage.tsx:350` — разделитель «•» (декоративный, но без `aria-hidden`).

**Решение:** заменить на `text-slate-500` (токен уже даёт 4.5:1 в обеих темах — это ровно тот случай, ради которого токен создавался). Декоративные «•»/«/» — `aria-hidden`.

### Д5 🟡 Декоративные сепараторы «/» в тикере — 1.17:1, без aria-hidden (450 замеров)

`MarketTicker.tsx:120`: `text-white/[0.08]` — почти невидимые «/» между инструментами бегущей строки. Как декор это допустимо, но это **текстовые узлы**: скринридеры зачитывают «слэш» между каждым тикером. В `OverviewPage.tsx:391` аналогичный сепаратор уже сделан правильно (`aria-hidden`) — привести MarketTicker к тому же паттерну.

### Д6 🟡 Пограничный контраст amber (4.26–4.44:1) — 18 случаев

- бейджи «Шорт» на `/liquidations` — **4.26:1** (11px, нужно 4.5);
- `text-amber-400` на числах в `/tools` (LIGHT-тема) — **4.44:1**;
- `text-amber-300/80` «подробнее ▾» — 4.3:1.

**Решение:** в LIGHT-теме амбер-тексты → `amber-600`; бейдж «Шорт» → `rose-300/rose-900` по образцу финансовых семантик либо снять прозрачность фона (`/80` → полный).

## 4. Мелкие замечания и расхождения документации с кодом

1. **DESIGN_SYSTEM §5 vs реальность:** заявлено «каждая кнопка снабжена `focus-visible: outline-cyan-400`» — в `src/` **0** классов `focus-visible:` (фокус работает через глобальный CSS-правило `index.css:404`). Работает, но документация описывает несуществующий паттерн — стоит поправить текст.
2. **Заявлено «минимальная высота кнопок 32px»** — на мобильных не выполняется (см. Д3). Либо исправить вёрстку, либо честно ограничить правило desktop-контекстом.
3. `uppercase` — ровно 20 (лимит достигнут): следующий статус-чип сломает тест. Стоит поднять осознанность: заменить 2–3 `uppercase` на `tracking-wide` нормального регистра.
4. Тикер в шапке перегружен на 390px (цена+дельта+стрелка при 11px) — читаемо, но на грани; при введении тёмного/светлого акцента можно поднять кегль до 12px, т.к. плотность строк это позволяет.
5. `/strategies` — 1619 DOM-элементов (втрое выше медианы), тяжелейшая страница: при добавлении контента стоит виртуализовать список версий.

## 5. Позитивная специфика, которую стоит сохранить

- **Токенная дисциплина идеальна**: 0 произвольных hex в TSX, инверсия шкал для LIGHT спроектирована, а не подобрана («slate-200 → тёмный текст» и т.д.).
- **Темы переключаются тотально** — ни одной неперекрашенной зоны из 576 ячеек сетки на 4 страницах, включая canvas-графики (CandleChart читает CSS-переменные через `getComputedStyle`).
- **Анти-FOUC**: inline-скрипт в `index.html` применяет тему до загрузки бандла.
- **Честные состояния** — деградация «ИСТОЧНИК НЕДОСТУПЕН» оформлена в едином компактном компоненте, пустые состояния не «пустые коробки», а информативные блоки.

## 7. Вывод

Дизайн CRYPTORA инженерно честен: почти все заявления дизайн-системы подтверждаются инструментальными проверками, что редкость. Ключевой риск — **невидимый**: из-за CSP продакшен никогда не показывал фирменную типографику, и никто не заметил, потому что все QA-прогоны шли на фолбэке. Закрытие Д1 (self-hosted шрифты) мгновенно вернёт проекту заявленный «premium terminal» вид, а Д2–Д6 доведут доступность до уровня, которым проект уже гордится в документации.

Шрифты в скриншотах — системные (сеть песочницы), что совпадает с текущим прод-рендером (см. Д1).*
