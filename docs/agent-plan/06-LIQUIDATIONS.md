> **Статус:** Выполнен (v0.6.0); конвейер переведён на фактический WS-поток и инварианты честности данных в **v0.8.2**  
> ⚠️ **ИНВАРИАНТ:** **CRYPTORA DOES NOT EXECUTE TRADES.**  
> Модуль ликвидаций предназначен исключительно для оценки зон каскадного рыночного давления и плечевого перекоса. Терминал не выставляет ликвидационные заявки и не совершает сделок. Обязательно соблюдается методологический дисклеймер: `Actual != Estimated`.

## 1. Выполненные задачи

### 1.1. Конвейер ликвидаций (`LiquidationPipeline`)
- Файл: `src/services/liquidations/LiquidationPipeline.ts`
- Прием и парсинг WebSocket сообщений `forceOrder` (Binance USD-M Futures).
- Агрегация скользящих метрик за 24 часа:
  - Суммарный объем принудительных ликвидаций (USD);
  - Объемы ликвидированных длинных (Long) и коротких (Short) позиций;
  - Long/Short ликвидационное соотношение (Ratio);
  - Разбивка по биржам (Binance, Bybit, OKX) и базовым активам (BTC, ETH, SOL и др.).

### 1.2. Расчетная модель кластеров риска (Estimated Liquidation Clusters)
- Математический расчет теоретических зон скопления ликвидаций на основе плечевых мультипликаторов ($10\times, 25\times, 50\times, 100\times$):
  $$\text{Long Liq Price} = \text{Current Price} \times \left(1 - \frac{1}{\text{Leverage}}\right)$$
  $$\text{Short Liq Price} = \text{Current Price} \times \left(1 + \frac{1}{\text{Leverage}}\right)$$
- Расчет плотности риска и ожидаемого ликвидационного объема в долларовом выражении.

### 1.3. Интеграция с UI и `LiveMarketDataProvider`
- Подключение метода `getLiquidations()` к `LiquidationPipeline.getInstance().getLiquidationSnapshot()`.
- Обновление страницы `src/pages/LiquidationsPage.tsx`:
  - Бейдж статуса потока, отражающий фактическое состояние данных (см. §1.4);
  - Блок расчетных кластеров ликвидаций с маркировкой `MODEL / ESTIMATED`;
  - Сохранение строгого юридического и методологического дисклеймера: фактические ликвидации бирж четко отделены от расчетных уровней модели.

### 1.4. Фактический транспорт потока и честность данных (v0.8.2)

**Что было исправлено.** До v0.8.2 модуль формально «принимал» `forceOrder`, но:

- метод `processBinanceForceOrder()` не вызывался ни из одного места проекта — фактического потока ликвидаций не существовало;
- `getLiquidationSnapshot()` восполнял отсутствие данных синтетическими константами (Long $62M, Short $28M, итог $90M, whale-событие $1.25M, разбивка бирж 52/28/20%, таймлайн из фиксированных баров);
- предзаполненные события хранились с `isDemo: false`, то есть выдавались за фактический биржевой поток;
- в идентификаторах событий использовался `Math.random()`.

Это противоречило RULES §1 («Данные vs Демо: обязательная маркировка»), RULES §3 (запрет `Math.random()` в рыночных данных) и AGENTS §3.1.

**Текущая реализация:**

| Компонент | Файл | Ответственность |
| --- | --- | --- |
| Транспорт потока | `src/services/realtime/BinanceFuturesLiquidationStream.ts` | WS `wss://fstream.binance.com/ws/!forceOrder@arr`, реконнект с экспоненциальной задержкой, состояния `idle / connecting / connected / reconnecting / unavailable` |
| Конвейер агрегации | `src/services/liquidations/LiquidationPipeline.ts` | Разбор payload, скользящее окно 24ч, агрегаты, разбивки, 3-часовые бары, статус данных |
| Жизненный цикл | `src/services/realtime/RealtimeFeedManager.ts` | Поток поднимается в `connect()` (LIVE-режим) и останавливается в `disconnect()` (DEMO) |

**Контракт честности (`LiquidationDataStatus`):**

| Статус | Условие | Поведение UI |
| --- | --- | --- |
| `LIVE_STREAM` | Есть фактически принятые события за 24ч | Пульсирующий бейдж LIVE, суммы из фактических событий |
| `AWAITING_STREAM` | Транспорт подключен, событий ещё нет | Явное сообщение об ожидании событий; нулевые агрегаты, `largestEvent: null` |
| `UNAVAILABLE` | Транспорт недоступен (нет WS/сети) | Сообщение о недоступности потока; никаких оценочных сумм |
| `DEMO` | Демонстрационный провайдер данных | Бейдж «ДЕМОНСТРАЦИОННЫЙ СРЕЗ» / `DEMO DATASET` |

**Инварианты, закреплённые тестами:** пустой конвейер не фабрикует агрегаты; события старше 24ч исключаются; id детерминирован; событие из биржевого потока никогда не помечается `isDemo: true`; `null`-транспорт честно переводит поток в `unavailable`.
