# 03-REALTIME — Этап 3: Потоковая передача данных через WebSockets и Движок аномалий

> **Статус:** Выполнен (v0.3.0)  
> ⚠️ **ИНВАРИАНТ:** **CRYPTORA DOES NOT EXECUTE TRADES.**  
> Потоковые WebSocket-каналы и движок детекции аномалий используются исключительно для сбора рыночных данных и аналитических наблюдений. Терминал не выставляет ордера и не совершает автоматических сделок.

## 1. Выполненные задачи

### 1.1. Клиент публичного WebSocket (`BinanceWebSocketClient`)
- Файл: `src/services/realtime/BinanceWebSocketClient.ts`
- Подключение к публичному шлюзу `wss://stream.binance.com:9443/stream` без необходимости API-ключей.
- Поддержка мультистриминга комбинированных потоков:
  - `<symbol>@ticker` (24h скользящее окно тикера);
  - `<symbol>@trade` (поток публичных сделок);
  - `<symbol>@depth20@100ms` (стакан цен 20 уровней L2).
- Автоматическое восстановление соединения при обрывах с экспоненциальным backoff (от 1 до 30 секунд).
- Синхронизация активных подписок при переподключении.
- Парсинг сырых сообщений биржи в типизированные сущности `TickerTick`, `TradeTick`, `OrderBookSnapshot` с фиксацией источника (`DataProvenance`).
- Инъекция конструктора сокета (`webSocketClass`) для изолированного тестирования без внешних сетевых зависимостей.

### 1.2. Внутренняя шина событий и троттлинг (`EventBus`)
- Файл: `src/services/realtime/EventBus.ts`
- Потокобезопасная pub/sub шина для тем:
  - `ticker:<symbol>` (например `ticker:BTC`), `ticker:*` (все котировки);
  - `trade:<symbol>`, `trade:*`;
  - `depth:<symbol>`;
  - `radar` (события аномалий);
  - `connection` (статус WebSocket).
- **Регулируемый троттлинг (Throttling 250ms):**
  - Буферизация высокочастотных тиков с интервалом сброса 250 мс для защиты UI от паразитных перерендеров и гарантирования 60 FPS в браузере.
  - Поддержка флага немедленной доставки (`immediate = true`) для критических алертов.

### 1.3. Математический движок детекции аномалий (`AnomalyEngine`)
- Файл: `src/services/realtime/AnomalyEngine.ts`
- **Volume Spike (Z-Score):**
  - Скользящее окно объемов ($N = 20$).
  - Математический расчет среднего ($\mu$) и среднеквадратичного отклонения ($\sigma$).
  - $Z = \frac{V - \mu}{\sigma}$.
  - При $Z \ge 3.0\sigma \rightarrow$ важность `HIGH`, при $Z \ge 2.0\sigma \rightarrow$ важность `MEDIUM`.
- **Price Move / Velocity:**
  - Отслеживание скорости изменения цены за короткий промежуток времени.
  - При $|\Delta P\%| \ge 4.0\% \rightarrow$ важность `HIGH`, при $|\Delta P\%| \ge 2.5\% \rightarrow$ важность `MEDIUM`.
- **Volatility Expansion:**
  - Отношение текущего размаха цены (high - low) к среднему историческому диапазону.
  - При расширении $\ge 2.5\times \rightarrow$ важность `HIGH`, при $\ge 1.8\times \rightarrow$ `MEDIUM`.
- **Защита от спама (Alert Cooldown):**
  - Встроенный период охлаждения (по умолчанию 30 сек на пару символ+тип) предотвращает дублирование идентичных событий.
  - Сгенерированные события имеют статус `isDemo: false` и метаданные расчетов.

### 1.4. Менеджер потоков (`RealtimeFeedManager`)
- Файл: `src/services/realtime/RealtimeFeedManager.ts`
- Синглтон-оркестратор, объединяющий `EventBus`, `AnomalyEngine` и `BinanceWebSocketClient`.
- Хранение актуального среза цен (`latestPriceMap`) и буфера недавних аномалий радара.

### 1.5. Интеграция с UI и слоем данных
- `MarketDataContext.tsx`:
  - Управление жизненным циклом соединения при переключении `demo` ↔ `live`.
  - Предоставление хуков `livePrices`, `realtimeStatus`, `subscribeSymbol`.
- `Header.tsx`:
  - Живой индикатор статуса WebSocket: `LIVE SPOT (WS ●)` при подключении, `WS ⟳` при реконнекте.
- `RadarPage.tsx`:
  - Переключение в режим `LIVE ANOMALY ENGINE` с получением событий от движка аномалий в реальном времени.
- `CoinDetailPage.tsx`:
  - Динамическое отображение живой цены тикера со световым индикатором тиков и бейджем биржевого источника (`LIVE SPOT: BINANCE`).
- `MarketPage.tsx`:
  - Реактивное обновление цен в сводной таблице инструментов.
