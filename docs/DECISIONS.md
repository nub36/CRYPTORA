# DECISIONS — Реестр архитектурных решений (ADR)

> **Статус:** Фиксация ключевых технологических и проектных развилок

---

## ADR-001: Запрет генерации всего продукта одним проходом
- **Контекст:** Попытка сразу реализовать сбор сокетов бирж, бэктест и ИИ-анализ неизбежно приведет к некачественному, хрупкому коду.
- **Решение:** Строгое фазирование. Этап 1 — полноценный, визуально завершенный терминал на контролируемых типизированных demo-данных с четкой маркировкой.

## ADR-002: Разделение провайдера данных (`MarketDataProvider`)
- **Контекст:** Фронтенд должен легко переключаться с демонстрационных данных на живой биржевой бэкенд на Этапе 2.
- **Решение:** Реализован единый интерфейс `MarketDataProvider`. На Этапе 1 используется `DemoMarketDataProvider`. Все страницы работают через React context/hooks, не зная о природе источника данных.

## ADR-003: Библиотека графиков — Lightweight Charts
- **Контекст:** Для финансового терминала требуются быстрые, профессиональные свечные графики с поддержкой темной темы, масштабирования и перекрестия, не перегружающие DOM.
- **Решение:** Выбрана зрелая индустриальная библиотека TradingView Lightweight Charts в сочетании с оптимизированными векторными SVG-спарклайнами для таблиц.

## ADR-004: Статус расчетных тепловых карт ликвидаций
- **Контекст:** Пользователи часто путают фактические ликвидации с прогнозными уровнями.
- **Решение:** Ввести строгое архитектурное разделение: биржевые принудительные ордера (`Actual liquidations`) и математические тепловые карты уровней (`Estimated / Model`), сопровождаемые обязательным визуальным предупреждением.

## ADR-005: Позиционирование AI в системе
- **Контекст:** Риск галлюцинаций LLM при работе с финансовыми цифрами.
- **Решение:** AI исключен из слоя вычислений. AI используется только на финальном этапе для генерации текстовых объяснений поверх проверенных чисел детерминированного аналитического движка.
